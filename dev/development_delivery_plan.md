# План нормализации, разработки и развертывания проекта

## Цель

Привести репозиторий ANACONDA Site к состоянию, в котором:

- код, документация, runtime и CI/CD описывают одну и ту же систему;
- локальная разработка воспроизводима;
- Этап 1 / Public MVP доводится до завершения без архитектурного шума;
- deploy-контур готов к безопасному переходу на `main` после выравнивания git-состояния;
- проект можно сопровождать без накопления мусора и битых артефактов.

## Текущее положение

Проект находится в конце **Этапа 1 / Public MVP**.

Подтверждено:

- локальный `web + api + postgres` контур уже поднимался;
- `GET /api/v1/health` и `POST /api/v1/leads` работают;
- frontend разбит на модульные сущности `sections / motion / ui / lib`;
- SQLAlchemy + Alembic приведены к единой схеме;
- CI/CD и Ansible уже доведены до release-based модели, но ветка `main` ещё не введена в рабочий процесс;
- репозиторий всё ещё загрязнён generated-артефактами, старым мусором и аномальным git-индексом.

## Главные проблемы

1. Git worktree/index находится в аномальном состоянии `deleted + untracked` почти по всему дереву.
2. Часть внутренних markdown-документов была повреждена кодировкой.
3. В репозитории присутствуют generated-артефакты среды (`__pycache__`, `.next`, bootstrap-логи, локальные служебные файлы).
4. Документация обновлялась неравномерно: часть файлов отражает текущее состояние, часть отстаёт или испорчена.
5. CI/CD-логика уже подготовлена под `main`, но реальный git-flow ещё не приведён к этому состоянию.

## Принцип внедрения

Работа выполняется по слоям, от самых рискованных к более прикладным.

## Фаза A. Санитарная нормализация репозитория

Цель:

- убрать подтверждённый мусор;
- восстановить читаемость ключевой документации;
- привести правила игнорирования файлов к нормальному виду.

Состав:

1. Очистка generated-артефактов.
2. Нормализация `.gitignore`.
3. Удаление устаревших role/doc-артефактов, которые больше не являются источником истины.
4. Перезапись критичных markdown-файлов в чистом UTF-8.

## Фаза B. Выравнивание внутренней документации

Цель:

- зафиксировать единый инженерный контур проекта.

Состав:

1. Нормализовать `dev/project_development_memory.md`.
2. Нормализовать план проекта и внутренние role-файлы.
3. Обновить docs по CI/CD, deploy, локальному запуску и migration discipline.
4. Явно зафиксировать blockers и ограничения.

## Фаза C. Git и release discipline

Цель:

- подготовить репозиторий к безопасному переходу на `main`.

Состав:

1. Отдельно диагностировать причину аномального git-индекса.
2. Выровнять worktree без ложных массовых удалений/добавлений.
3. Только после этого переводить release flow на `main`.
4. После выравнивания — commit, push, default branch switch и включение production trigger.

## Фаза D. Завершение Этапа 1 / Public MVP

Цель:

- закрыть основной публичный deliverable проекта.

Состав:

1. Ручная mobile-first QA страниц `/` и `/contacts`.
2. Финальная шлифовка hero, CTA, motion и текстов.
3. Сверка с `dev/v1/anaconda_stage_1_public_mvp_tz.md`.
4. Закрытие остаточных расхождений между дизайном, кодом и docs.

## Фаза E. CI/CD и production readiness

Цель:

- сделать release flow реально эксплуатационным.

Состав:

1. Проверить workflow-файлы и документацию на консистентность.
2. Подготовить список обязательных GitHub secrets и host prerequisites.
3. Проверить release-based deploy и rollback на dry-run уровне.
4. Подготовить ручной Ansible-операционный контур как backup-маршрут.

## Что требуется от пользователя

Если понадобится подключать production-контур, пользователь может передавать значения через локальные env-файлы, но до выравнивания git-состояния и релизной ветки эти значения не должны считаться production-ready release configuration.

На текущем шаге от пользователя не требуется дополнительных данных для локальной нормализации репозитория.

## Критерий успеха текущей итерации

Текущая итерация считается успешной, если:

- репозиторий очищен от явного generated-мусора;
- ключевые внутренние docs снова читаемы;
- memory и план проекта приведены к нормальному состоянию;
- зафиксирован ясный backlog по git, Этапу 1 и CI/CD.
