# ANACONDA SITE — Visual Design Project v1.0

## 0. Роль документа

Этот документ описывает визуальный дизайн-проект сайта **Anaconda** как продающей enterprise-страницы для технологического B2B-продукта.

Документ предназначен для:

- дизайнера интерфейса;
- frontend-разработчика;
- арт-директора;
- владельца продукта;
- подрядчика, который будет реализовывать сайт.

Цель — создать не просто красивый лендинг, а визуальную систему, которая продаёт зрелость, контроль, интеллект и технологическую надёжность продукта.

---

# 1. Главная визуальная идея

## 1.1. Формула

**Anaconda Site = Dark Enterprise Luxury + Intelligent Control + Material Technology**

Сайт должен ощущаться как:

- дорогая технологическая система;
- интерфейс для людей, которые принимают решения;
- продукт не для игрушечного стартапа, а для бизнеса с деньгами;
- спокойная сила, а не визуальный шум;
- цифровая архитектура, а не обычный маркетинговый лендинг.

## 1.2. Ключевой образ

**Хаос бизнеса сжимается в управляемую структуру.**

Визуально это выражается через:

- тёмные графитовые поверхности;
- благородный зелёный акцент;
- стеклянные панели;
- металл;
- тонкие линии интерфейса;
- мягкие, но дорогие подсветки;
- строгую сетку;
- крупную уверенную типографику;
- отсутствие дешёвого AI-glow и чрезмерных округлений.

---

# 2. Дизайн-характер

## 2.1. Каким сайт должен быть

Сайт должен быть:

- взрослым;
- дорогим;
- технологичным;
- строгим;
- уверенным;
- понятным;
- немного холодным;
- премиальным;
- инженерно точным;
- визуально глубоким.

## 2.2. Каким сайт не должен быть

Запрещено:

- кислотный AI-градиент;
- чрезмерные закругления карточек;
- “пластилиновый” SaaS-стиль;
- дешёвый glassmorphism из Dribbble;
- ярко-синий startup-style;
- crypto/Web3-эстетика;
- перегруженные 3D-иллюстрации;
- мультяшные иконки;
- интерфейс “для школьников”;
- декоративные элементы без функции.

---

# 3. Визуальная метафора материалов

## 3.1. Основные материалы

Сайт строится как система материалов:

1. **Graphite Surface** — основная тёмная матовая поверхность.
2. **Carbon Depth** — глубокий почти чёрный фон с лёгкой текстурой.
3. **Brushed Metal** — металлические разделители, рамки, элементы статуса.
4. **Intelligent Glass** — стеклянные панели с управляемой прозрачностью.
5. **Noble Green Signal** — зелёные акценты как индикаторы контроля.
6. **Ivory White Text** — чистый текстовый контраст.

## 3.2. Почему материалы важны

Материалы должны создавать ощущение, что Anaconda — это не сайт, а **цифровой командный центр**.

Стекло показывает прозрачность.
Металл показывает надёжность.
Графит показывает серьёзность.
Зелёный сигнал показывает интеллект и управляемость.
Белый текст показывает ясность.

# 5. Типографика

## 5.1. Общий принцип

Типографика должна выглядеть как архитектура.

Не “модно”, не “креативно ради креатива”, а:

- крупно;
- уверенно;
- структурно;
- с хорошим воздухом;
- с дорогой посадкой текста.

## 5.2. Шрифтовая пара

### Вариант A — строгий enterprise

- Заголовки: **Manrope** / **Inter Tight**
- Текст: **Inter**
- Интерфейсные подписи: **JetBrains Mono** или **IBM Plex Mono**

### Вариант B — более премиальный

- Заголовки: **Neue Haas Grotesk / Söhne / Suisse Int’l** если доступны лицензии.
- Альтернатива без лицензий: **Geist**, **Inter Tight**, **Manrope**.
- Текст: **Inter / Geist Sans**.
- Технические подписи: **JetBrains Mono**.

## 5.3. Настройка заголовков

Для крупных заголовков использовать слегка сжатую или tight-типографику.

```css
.hero-title {
  font-family: var(--font-display);
  font-size: clamp(56px, 8vw, 128px);
  line-height: 0.92;
  letter-spacing: -0.075em;
  font-weight: 620;
}
```

Важно: заголовок должен быть большим, но не кричащим.

## 5.4. Иерархия

### H1

- 72–128 px desktop;
- 48–64 px tablet;
- 40–48 px mobile;
- line-height: 0.9–1.0;
- letter-spacing: от -4% до -7.5%.

### H2

- 44–72 px desktop;
- line-height: 0.95–1.05;
- letter-spacing: -4%.

### H3

- 24–36 px;
- line-height: 1.1;
- letter-spacing: -2%.

### Body

- 17–20 px desktop;
- 16–18 px mobile;
- line-height: 1.55–1.7.

### Microcopy

- 12–14 px;
- uppercase допускается;
- letter-spacing: 0.08em–0.14em;
- использовать для технических статусов, бейджей, подписей.

# 7. Система стекла — Intelligent Glass

## 7.1. Принцип

Стекло в Anaconda — не украшение.

Оно должно означать:

- прозрачность процессов;
- наблюдаемость;
- слой контроля поверх хаоса;
- технологическую зрелость.

Стекло нельзя использовать везде. Оно должно появляться там, где интерфейс показывает управление, аналитику, командный центр или AI-контур.

## 7.2. Визуальные параметры стекла

Правильное стекло:

- не слишком прозрачное;
- имеет тонкую металлическую рамку;
- содержит внутреннюю подсветку;
- имеет лёгкий blur;
- сохраняет читаемость текста;
- не выглядит как “мыльный пузырь”.

## 7.3. CSS-переменные стекла

```css
:root {
  --glass-bg-rgb: 18, 24, 21;
  --glass-bg-alpha: 0.58;
  --glass-border-alpha: 0.16;
  --glass-blur: 18px;
  --glass-saturation: 145%;
  --glass-radius: 18px;
  --glass-shadow-alpha: 0.28;
  --glass-inner-highlight: rgba(255, 255, 255, 0.06);
  --glass-green-glow: rgba(61, 220, 151, 0.12);
}
```

## 7.4. Базовый класс стекла

```css
.u-glass {
  position: relative;
  background:
    linear-gradient(
      180deg,
      rgba(255, 255, 255, 0.055),
      rgba(255, 255, 255, 0.018)
    ),
    rgba(var(--glass-bg-rgb), var(--glass-bg-alpha));
  border: 1px solid rgba(220, 235, 228, var(--glass-border-alpha));
  border-radius: var(--glass-radius);
  backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturation));
  -webkit-backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturation));
  box-shadow:
    0 24px 80px rgba(0, 0, 0, var(--glass-shadow-alpha)),
    inset 0 1px 0 var(--glass-inner-highlight),
    inset 0 -1px 0 rgba(0, 0, 0, 0.18);
}
```

## 7.5. Стеклянная рамка с металлическим краем

```css
.u-glass::before {
  content: "";
  position: absolute;
  inset: 0;
  border-radius: inherit;
  padding: 1px;
  background: linear-gradient(
    135deg,
    rgba(255, 255, 255, 0.22),
    rgba(61, 220, 151, 0.14),
    rgba(255, 255, 255, 0.04),
    rgba(127, 138, 133, 0.18)
  );
  mask:
    linear-gradient(#000 0 0) content-box,
    linear-gradient(#000 0 0);
  mask-composite: exclude;
  pointer-events: none;
}
```

## 7.6. Модификаторы стекла

### 7.6.1. Лёгкое стекло

Для header, маленьких бейджей, навигации.

```css
.u-glass--light {
  --glass-bg-alpha: 0.36;
  --glass-blur: 14px;
  --glass-border-alpha: 0.12;
  --glass-shadow-alpha: 0.16;
}
```

### 7.6.2. Плотное стекло

Для больших панелей и форм.

```css
.u-glass--solid {
  --glass-bg-alpha: 0.72;
  --glass-blur: 22px;
  --glass-border-alpha: 0.20;
  --glass-shadow-alpha: 0.34;
}
```

### 7.6.3. Сигнальное стекло

Для AI-панелей, CTA и важных продуктовых визуализаций.

```css
.u-glass--signal {
  box-shadow:
    0 28px 90px rgba(0, 0, 0, 0.34),
    0 0 48px var(--glass-green-glow),
    inset 0 1px 0 rgba(255, 255, 255, 0.07);
}
```

### 7.6.4. Металлическое стекло

Для карточек с ощущением command surface.

```css
.u-glass--metal {
  background:
    linear-gradient(145deg, rgba(255,255,255,0.07), rgba(255,255,255,0.015)),
    linear-gradient(180deg, rgba(45,56,51,0.72), rgba(12,16,14,0.72));
  border-color: rgba(185, 196, 190, 0.18);
}
```

## 7.7. Настройка радиусов

Критически важно: не использовать большие “AI-rounded” скругления.

Рекомендации:

```css
--radius-xs: 6px;
--radius-sm: 10px;
--radius-md: 14px;
--radius-lg: 18px;
--radius-xl: 22px;
```

Максимальный радиус для большинства карточек: **18px**.

Очень крупные 32px+ радиусы не использовать, кроме специальных hero-поверхностей и только если это обосновано.

# 9. Header

## 9.1. Роль header

Header должен выглядеть как элемент системы управления, а не обычное меню.

Он должен быть:

- sticky;
- стеклянным;
- тонким;
- спокойным;
- всегда читаемым;
- без лишнего визуального веса.

## 9.2. Структура

Слева:

- знак / логотип Anaconda.

Центр:

- Продукт;
- Архитектура;
- Внедрение;
- Безопасность;
- Контакты.

Справа:

- вторичная кнопка “Получить консультацию”;
- primary CTA “Запросить демо”.

## 9.3. Визуал

```css
.site-header {
  position: sticky;
  top: 16px;
  z-index: 100;
  width: min(1240px, calc(100% - 32px));

```

Header не должен занимать всю ширину как корпоративный портал. Лучше сделать его плавающей стеклянной командной панелью.

# 10. Hero Section

## 10.1. Цель hero

За 5 секунд пользователь должен понять:

1. Что такое Anaconda.
2. Для кого это.
3. Почему это серьёзно.
4. Какой хаос она решает.
5. Что делать дальше.

## 10.2. Предлагаемый headline

Вариант 1:

**Соберите хаос продаж, чатов и 1С в единую систему управления**

Вариант 2:

**Anaconda превращает коммуникационный хаос бизнеса в управляемую нервную систему**

Вариант 3:

**Единое окно для продаж, данных, сотрудников и AI-контроля**

## 10.3. Subheadline

Anaconda подключается к вашим текущим системам — 1С, CRM, почте, мессенджерам и ERP — и собирает процессы в единый защищённый контур без разрушения существующей инфраструктуры.

## 10.4. Hero layout

Desktop:

- левая часть: текст, trust-сигналы, CTA;
- правая часть: большая command-панель / визуализация продукта;
- фон: carbon/graphite, тонкая сетка, мягкая зелёная подсветка.

Соотношение:

- 52% текст;
- 48% продуктовый визуал.

## 10.5. Hero visual

Не использовать обычный mockup ноутбука как главный visual.

Лучше:

- стеклянная command-панель;
- внутри — единая лента событий;
- слева — источники хаоса: Telegram, Email, 1С, Excel, звонки;
- справа — структурированный поток Anaconda;
- сверху — статус: “On-Premise / Secure / AI-Ready”.

## 10.6. Trust signals в hero

Микро-плашки:

- On-Premise Ready
- 1С / MSSQL / ERP Integration
- AI Knowledge Core
- Role-Based Access
- Audit Log

Визуал: маленькие металлические бейджи с моноширинным текстом.

# 11. Главная narrative-анимация: Chaos → Control

## 11.1. Смысл

Это ключевая визуальная сцена сайта.

Пользователь должен увидеть не абстрактный AI, а то, как хаос реального бизнеса собирается в порядок.

## 11.2. Сценарий

1. На экране появляются разрозненные источники:
   - Telegram;
   - WhatsApp;
   - Email;
   - 1С;
   - Excel;
   - CRM;
   - звонки;
   - склад;
   - заявки с сайта.

2. Они находятся в разных частях экрана, слегка дрейфуют.

3. При скролле линии начинают связывать их с центром.

4. Центральная стеклянная панель Anaconda усиливается.

5. Хаотичные элементы превращаются в упорядоченную ленту событий.

6. Финальный кадр: единый интерфейс управления.

## 11.3. Визуальный стиль анимации

- тонкие линии;
- мягкие перемещения;
- без резких рывков;
- без “частиц ради частиц”;
- зелёный glow только в момент структурирования;
- motion должен объяснять продукт.

## 11.4. GSAP-реализация

Desktop:

```js
gsap.timeline({
  scrollTrigger: {
    trigger: '.chaos-section',
    start: 'top top',
    end: '+=180%',
    scrub: 1,
    pin: true,
  }
})
.to('.chaos-node', {
  x: 0,
  y: 0,
  scale: 0.72,
  opacity: 0.18,
  stagger: 0.04,
})
.to('.control-panel', {
  opacity: 1,
  scale: 1,
  filter: 'blur(0px)',
}, '<')
.to('.flow-line', {
  strokeDashoffset: 0,
  opacity: 1,
  stagger: 0.03,
}, '<');
```

Mobile:

- убрать сложный pin на слабых устройствах;
- сделать вертикальный stack;
- элементы собираются сверху вниз;
- меньше blur;
- меньше glow.

# 12. Bento Grid продукта

## 12.1. Роль

Bento Grid должен объяснить продукт через крупные смысловые модули.

Не делать много одинаковых карточек.

## 12.2. Карточки

### 1. Единое окно коммуникаций

Показывает: чаты, почта, заявки, звонки в одной ленте.

### 2. Интеграция с 1С / ERP

Показывает: данные не копируются руками, а приходят в контекст.

### 3. AI-контур знаний

Показывает: корпоративная память, поиск, подсказки менеджеру.

### 4. Контроль сотрудников и процессов

Показывает: роли, активность, статусы, bottlenecks.

### 5. On-Premise безопасность

Показывает: данные внутри контура компании.

### 6. Аналитика денег и заявок

Показывает: путь от лида до оплаты.

## 12.3. Визуал bento

- большие карточки;
- много воздуха;
- разные размеры;
- каждая карточка имеет собственный мини-интерфейс;
- минимум иконок, максимум интерфейсной демонстрации.

# 19. Motion System

## 19.1. Главный принцип

Motion объясняет систему, а не развлекает.

## 19.2. Допустимые анимации

- fade in;
- soft slide;
- line draw;
- stagger reveal;
- signal pulse;
- data flow;
- glass highlight sweep;
- hover elevation.

## 19.3. Запрещённые анимации

- агрессивный parallax;
- летающие 3D-объекты без смысла;
- бесконечные particles;
- twitchy motion;
- gaming UI;
- слишком быстрые AI-пульсации.

## 19.4. Timing

```css
--motion-fast: 160ms;
--motion-base: 240ms;
--motion-slow: 420ms;
--motion-page: 700ms;
```

Easing:

```css
--ease-out-premium: cubic-bezier(0.16, 1, 0.3, 1);
--ease-in-out-premium: cubic-bezier(0.65, 0, 0.35, 1);
```

# 23. Mobile design

## 23.1. Принцип

Mobile — это не уменьшенный desktop.

На мобильном нужно:

- меньше эффектов;
- меньше стекла;
- меньше blur;
- больше читаемости;
- sticky CTA;
- быстрый доступ к форме.

## 23.2. Mobile Hero

- headline максимум 4–6 строк;
- CTA сразу под текстом;
- trust badges горизонтальным scroll;
- command visual ниже, упрощённый.

## 23.3. Mobile Glass

Blur уменьшить:

```css
@media (max-width: 768px) {
  :root {
    --glass-blur: 10px;
    --glass-bg-alpha: 0.74;
  }
}
```

На мобильном читаемость важнее эффекта.

# 24. Accessibility и читаемость

## 24.1. Контраст

Текст на стекле должен быть читаемым.

Правило:

- если background blur мешает тексту — увеличить плотность стекла;
- если glow мешает тексту — убрать glow;
- если фон слишком шумный — добавить overlay.

## 24.2. Reduced motion

Обязательно:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 25.1. CSS architecture

Рекомендуется:
