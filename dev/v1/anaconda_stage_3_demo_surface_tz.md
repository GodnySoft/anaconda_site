# Техническое задание — Этап 3 # ANACONDA Demo Surface  ## Демонстрационная рабочая поверхность менеджера  ---  ## 1. Цель этапа  Разработать отдельную demo-страницу, которая визуально показывает, как выглядит реальная рабочая поверхность менеджера внутри ANACONDA.  Главная задача:  не рассказывать о системе словами, а дать пользователю увидеть, как менеджер работает внутри единого окна.  Страница должна:  - вызывать эффект «я понял, как это работает»; - показывать ценность системы за 15–20 секунд; - демонстрировать работу с клиентом, а не абстрактную CRM; - усиливать доверие к продукту; - закрывать пользователя на аудит / demo call.  Главная мысль:  **ANACONDA — это центр управления менеджера, где клиент, коммуникации, счета и действия находятся в одном месте.**  ---  ## 2. Технологический стек  ### Frontend  - Next.js 14+ - React 18+ - TypeScript - Tailwind CSS - Framer Motion - Interactive UI demo components - SVG flows  ### Backend  На этапе 3 полноценный backend не требуется.  Используется demo-data layer:  - mock API - local demo state - future-ready API contracts  ### Runtime  - Docker - Docker Compose - Nginx  ### Quality  - ESLint - strict TypeScript - Lighthouse - mobile QA  ---  ## 3. Страница  ### URL  `/demo`  ## Основные блоки  1. Header 2. Intro Hero 3. Demo Workspace 4. Контрагенты и иерархия 5. Центральный чат 6. Правая карточка контрагента 7. Действия менеджера 8. AI-подсказки 9. CTA на аудит / demo session 10. Footer  ---  ## 4. Hero Section  ### Заголовок  # Так выглядит работа внутри ANACONDA  ### Подзаголовок  Не десять программ, не потерянные сообщения и не ручной перенос данных.  Один экран, где менеджер видит клиента, историю общения, счета, оплату и следующие действия.  ### CTA  - Заказать демонстрацию - Запросить аудит  ---  ## 5. Demo Workspace Layout  Главная зона страницы — визуальный интерфейс рабочей поверхности.  ## Структура  ### Левая колонка  # Контрагенты  Как в Slack / Discord:  - список компаний - новые сообщения - активность - статусы - приоритеты  Примеры:  - ООО ПромСнаб - КраснодарЭлектро - ТрансАзия - ЮгКабель  ---  ### Внутри контрагента  ## Иерархия  Компания → Отдел → Контакт  Пример:  ООО ПромСнаб  → Бухгалтерия → Отдел продаж → Закупки → Руководство  Внутри:  - Иван Петров - Мария Иванова - Сергей Орлов  Это должно визуально раскрываться как tree structure.  ---  ## 6. Источники контакта  У каждого контакта должны отображаться источники:  - Telegram - WhatsApp - MAX - Email - Телефон - сайт  Менеджер всегда видит:  откуда пришло сообщение.  Формат:  иконка + source badge.  ---  ## 7. Центральное окно  # Рабочий чат  Показываем:  - переписку - входящие сообщения - историю действий - звонки - документы - счета - внутренние комментарии - задачи  Важно:  должно быть ощущение живой рабочей системы, а не макета CRM.  Пример:  Клиент пишет в Telegram → менеджер отвечает → система подтягивает карточку → можно выставить счет.  ---  ## 8. Правая панель  # Карточка контрагента  Отображать:  - задолженность - история оплат - активные счета - последние документы - подбор товара - остатки - рекестр взаимодействий - статус клиента - реквизиты  ---  ## 9. Действия менеджера  Кнопки:  - Выставить счет - Выбрать товар - Запросить оплату - Передать клиенту менеджеру - Создать задачу - Поставить напоминание - Создать внутренний комментарий  Важно:  кнопки должны визуально объяснять workflow.  ---  ## 10. AI-подсказки  Отдельный небольшой блок:  # AI рекомендует  Примеры:  - клиент просрочил оплату - был похожий кейс 2 месяца назад - рекомендуется предложить альтернативный товар - клиенту нужен повторный контакт  Важно:  AI не должен выглядеть как отдельный чат.  Он должен быть частью рабочего процесса.  ---  ## 11. CTA Section  ### Заголовок  # Хотите увидеть это на своих данных?  Мы можем развернуть demo-контур и показать, как ANACONDA будет работать именно в вашей компании.  ### Кнопка  `Запросить персональную демонстрацию`  Используется существующий LeadForm.  ---  ## 12.
