# ANACONDA — Проектная структура разработки сайта

## Роль сайта

Сайт ANACONDA — это не просто лендинг.

Это первая точка доверия, объясняющая клиенту:

- почему в компании возникает хаос;
- почему сотрудники теряют заявки и клиентов;
- почему 1С, Excel, Telegram, почта и звонки не работают как единая система;
- как ANACONDA превращает этот хаос в управляемую структуру.

Главная задача сайта:

**за 30 секунд показать, как разрозненные данные превращаются в единое окно управления бизнесом.**

Мы не ломаем действующую систему.

Мы аккуратно внедряемся в уже существующую инфраструктуру компании.

ANACONDA:

- подключается к 1С

- интегрируется с почтой
- подключает Telegram, WhatsApp, MAX
- связывается с телефонией
- собирает Excel и старые базы

Мы не делаем «снос и стройку заново».

Мы создаем надстройку — цифровой симбионт.

Он обволакивает существующий бизнес, убирает хаос и постепенно переводит компанию на современную управляемую систему.

Это позволяет:

- быстрее адаптироваться к рынку
- внедрять автоматизацию без остановки бизнеса

## Hero visual: chaos → order

## Desktop

Слева и вокруг экрана расположены карточки-источники:

- Telegram
- WhatsApp
- MAX
- Email
- Excel
- 1С
- База данных
- Звонки

В центре — окно ANACONDA.

Анимация:

1. При загрузке карточки источников слегка плавают.
2. Линии данных тянутся от источников к центральному окну.
3. Внутри центрального окна появляется чат менеджера.
4. Сообщение клиента помечается источником: `Telegram`, `Email`, `MAX`.
5. Справа внутри окна появляется карточка контрагента.
6. Появляется действие: `Выставить счет`.

Важно:

- анимация должна объяснять систему, а не отвлекать;
- использовать transform и opacity;
- не анимировать layout-свойства;
- не перегружать страницу canvas/three.js на первом этапе;
- SVG-линии допустимы;
- бесконечное движение только очень мягкое.

## Mobile

На мобильных:

- карточки источников идут горизонтальным scroll-row или компактной сеткой 2x4;
- центральное окно ANACONDA идет ниже;
- анимация упрощенная:
  - fade-in;
  - легкое появление линий;
  - последовательное появление сообщений;
- не использовать тяжелую scroll-driven анимацию;
- важнее скорость и читаемость.

## 9.9. Анимация

## Общие правила

- анимация должна помогать понять продукт;
- не использовать тяжелые эффекты на mobile;
- уважать `prefers-reduced-motion`;
- не делать бесконечные яркие эффекты;
- использовать transform, opacity, SVG stroke-dashoffset;
- не анимировать width, height, top, left без необходимости.

## Hero animation

### Desktop sequence

1. Sources appear
2. Data lines pulse
3. Central window appears
4. Chat messages appear one by one
5. Counterparty card slides in
6. Invoice action appears
7. CTA becomes active

### Mobile sequence

1. Heading appears
2. Source chips appear
3. Central window appears
4. 2–3 messages appear
5. CTA appears

## Scroll animation

- секции появляются при входе во viewport;
- карточки появляются stagger-эффектом;
- timeline “Как работает” раскрывается по шагам;
- на mobile duration короче.

## 9.10. Производительность

Требования:

- Lighthouse mobile не ниже 85;
- изображения WebP/AVIF;
- SVG вместо тяжелых картинок там, где возможно;
- lazy load для нижних секций;
- не использовать Three.js на Этапе 1;
- не использовать тяжелые particle effects;
- минимизировать JS в hero;
- форма должна работать быстро даже при слабом интернете.

## 9.11. Mobile-first требования

Обязательно проверить:

- 360px ширина;
- 390px iPhone;
- 768px tablet;
- desktop 1440px.

На mobile:

- header не перекрывает контент;
- CTA видимы;
- карточки читаемые;
- форма удобная;
- hero не занимает слишком много высоты;
- все кнопки имеют достаточную область нажатия;
- нет горизонтального скролла страницы.
